# site/ — the landing page

The paid front door. One page, no framework, no external requests, and every motion
example on it is a real file this repository rendered.

---

## What it is

Vite + vanilla TypeScript + GSAP. Self-hosted IBM Plex Sans and IBM Plex Mono. No React,
no Tailwind, no CDN, no analytics, no font service, no external request of any kind at
runtime — `scripts/verify-content.mjs` fails the build if `dist/index.html` contains a
single `src="http…"` or `href="http…"`.

| | |
|---|---|
| Built JS | 16.7 kB app + 70.0 kB GSAP = **86.7 kB** uncompressed, **34.2 kB gzipped** |
| CSS | 22.7 kB (5.1 kB gzipped) |
| HTML | 43.7 kB (8.5 kB gzipped) |
| External requests | **0** |
| Fonts | self-hosted, `font-display: swap`, latin subset only |
| Motion | GSAP for the hero canvas; `prefers-reduced-motion` disables every reveal |

## The source of truth for the offer

`licence.json` at the repo root holds the prices, the tier lists and the rendering
policy. The site imports it, the MCP server generates from it, and
`scripts/verify-content.mjs` fails the build if `dist/index.html` disagrees with it by
so much as a bullet point. **The page and the server cannot drift apart**, because
there is only one copy of the price.

Same for the clips: `src/clips.json` holds the prompt, title, duration, stack and alt
text for each of the four examples, and `src/data/clip-manifest.json` (generated by
`scripts/sync-clips.mjs`) holds which rendered files actually exist. The build checks
that all four prompts, titles, durations, stacks and alt texts survive into
`dist/index.html`.

## The four examples are real

`site/public/clips/` holds four rendered MP4s and four posters. They were rendered by
the compositions in `clips/src/`, in this repository, by the skills this product ships.

| id | duration | stack | poster frame |
|---|---|---|---|
| `launch-title` | 0:14 | remotion | 3.5s |
| `kinetic-type` | 0:09 | remotion | 3.4s |
| `product-loop` | 0:21 | remotion + ffmpeg | 10.5s |
| `footage-title` | 0:16 | remotion + montage bridge | 6.0s |

All 1280×720, 30fps, h264. The poster times are chosen, not frame 0: three of the four
clips open on an empty canvas, and a poster that shows an empty frame lies about what
the clip contains. `clips/render-all.sh` carries the same timestamps so a re-render
reproduces the same posters.

The prompts on the page are the prompts that made the clips. Where the first draft of
the manifest and the render disagreed, the manifest was corrected to the render — the
product loop has **four** stages, not three beats, and the kinetic type is **six words
on six lines**, not "six words across three lines". The alt text was corrected the same
way.

The source footage inside `footage-title` is a **generated stand-in**, not customer
footage, and `clips.json` says so in the note that ships with the manifest.

## Honesty rules the build enforces

`scripts/verify-content.mjs` fails the build on any of these:

- a clip prompt, title, duration, stack or alt text that is missing or wrong
- a price, tier name or tier bullet that disagrees with `licence.json`
- `$149` or `$599` left anywhere on the page
- a banned word: *transform, unlock, empower, reimagine, revolutionize, supercharge,
  seamless, elevate, game-changing, get started*
- an emoji or pictograph
- a `<video>` without `aria-label` or `muted`, an `<img>` without `alt`
- more than one `h1`, or a heading level jump
- any external `src`/`href`
- a domain with a TLD, or a `rel="canonical"` link
- a media file under 1 kB in `public/clips/`

The banned-word scan knows that `text-transform` is a CSS property, not copy, and that
the word appearing inside the GSAP vendor chunk is library code rather than page copy.
Both are reported as notes, not failures.

## The domain

The domain word `motionmaster` is written in exactly one place in the built page — a
single `<meta name="site-domain">` tag. The TLD has not been chosen and the domain has
not been purchased, so no URL with a suffix appears on the page, in a canonical link, in
the OpenGraph tags, or in the footer. The build fails if one does.

## Layout, verified not assumed

Checked with Chrome Headless Shell over the DevTools protocol, against the built site
served by `vite preview`:

- **320, 375, 390, 430, 768, 1024, 1280, 1440 px** — `scrollWidth` equals `innerWidth`
  at every one. No horizontal overflow anywhere.
- **Touch targets** — no link or button under 44px. The brand link in the header was
  24px and was padded to 44px.
- **WCAG AA contrast** — every visible text node on the page was resolved against its
  effective background and measured. **0 failures** at 4.5:1 for body text and 3:1 for
  large text. Reproduce with `scripts/contrast.mjs`.
- **Reveal animations** — the `motion-ok` class is added by JS *after* the observer and
  the 2.5s safety net exist, so content can never be left hidden. With JavaScript off,
  or with reduced motion, nothing is hidden at all.

Two real layout bugs were found and fixed this way: the storyboard table and the code
sample were widening the page at 320px (grid and flex children default to
`min-width: auto`, which stops their own scroll boxes from working), and the clip
metadata line had `white-space: nowrap` around a long stack string.

## Design territory

"The Film Lab". Light canvas `#F4F4F2`, ink `#111113`, muted `#6B6B70`, hairline
`#DDDEDA`, accent `#FF4A1C` on CTAs and large type only (`#D63A12` for small text on
light), player `#0E0E10`. IBM Plex Sans for display, IBM Plex Mono for labels and
metadata.

The signature is a **56px frame rail** down the left edge carrying a live timecode that
changes with the section you are in. On mobile it becomes a 2px line across the top.

No indigo, no violet, no gradient mesh, no glassmorphism, no card grid, no emoji, no
stock logos, no testimonials, no "trusted by", no fake user counts.

## The copy

It argues one thing: *describe the video, get the file.* It leads with a real clip and
its real prompt, explains the three steps, shows what is in the box, answers the four
objections a buyer actually has, then prices it.

The two prices are the founder's. The copy does not claim what the evidence ledger
cannot support — there is no "lifetime updates", no "priority support", no "team seats",
no render-speed number, and no hosted-render allowance figure, because that number has
not been decided. When the number is decided it goes in `licence.json` and the page
picks it up.

## Run it

```bash
cd site
npm install
npm run dev        # http://127.0.0.1:5173
npm run build      # tsc --noEmit && vite build && verify-content.mjs
npm run preview    # http://127.0.0.1:4173
```

`npm run build` fails on any content drift, any banned word, any missing alt text and
any external request. That is the point of it.

## Known gaps

- **The checkout is not connected.** The panel states the tier and the price and says
  plainly that nothing has been charged. No processor is chosen yet.
- **The hosted render allowance is `null`.** The page says Studio includes one and that
  the size is confirmed in the checkout receipt. No number appears because no number
  has been decided. Set it in `licence.json` and the page updates itself.
- **The domain has no TLD.** One meta tag, one place, no URL published.
